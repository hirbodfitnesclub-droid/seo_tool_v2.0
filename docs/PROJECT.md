# PROJECT.md — LinkMesh Lite (ابزار رتبه‌بندی لینک داخلی)

## هدف بیزینس
ابزاری سبک و تک‌منظوره: دو فایل CSV (صفحات سایت + ایمپرشن) را می‌گیرد و برای هر صفحه، ۲۰ تا ۳۰ لینک داخلیِ **مرتبط، متنوع و قابل‌توضیح** پیشنهاد می‌دهد (طبق مدل «دیوار→حلقه→پُرسازی»)، و با یک دکمهٔ هوش مصنوعی خروجی را نهایی/پولیش می‌کند. فاز فعلی: نهال‌گشت (تور مسافرتی).

## پرسونای هدف
کارشناس SEO که کدنویس نیست؛ CSV آپلود می‌کند، خروجی را می‌بیند، و export می‌گیرد.

## وضعیت: پروژهٔ نو از صفر (Zero-to-One)
پروژهٔ قبلی (`seo_tool_2.0`) به‌خاطر لایه‌های موروثیِ سنگین کنار گذاشته شد. این نسخه **از صفر و مینیمال** ساخته می‌شود: بدون دیتابیس، بدون صف، بدون IDF، بدون چندپروژه‌ای. منطق کامل: `ARCHITECTURE.md` (خودبسنده).

## فلسفهٔ معماری
ربط، شعاعی است: هر کاندیدا اول از **دیوارها** (مرز اسپم، حذف مطلق) رد می‌شود؛ بعد در یک **حلقه** (شعاع معنایی) می‌نشیند؛ بعد از مرکز به بیرون **پُر** می‌شود تا ۲۰–۳۰ لینک، بدون شکستن هیچ دیواری. هر لینک باید قابل‌توضیح باشد.

## پشته تکنولوژی (Tech Stack)
| لایه | ابزار |
|---|---|
| فریم‌ورک UI | React 18 + Vite |
| زبان | TypeScript |
| استایل | Tailwind CSS v3 (RTL، فارسی، تم emerald/blue) |
| پارس/خروجی CSV | Papa Parse v5 |
| پردازش | یک Web Worker نازک (محاسبهٔ موتور خارج از Main Thread) |
| هوش مصنوعی | Gemini API (دکمهٔ نهایی‌سازی) |
| state | useState + useContext (درون‌حافظه) |
| ماندگاری | فقط `localStorage` برای کلید API |

## نبایدهای سخت‌گیرانه (Anti-Patterns) — مطلق
| ممنوع | به‌جایش |
|---|---|
| **هیچ دیتابیسی (Dexie/IndexedDB/SQLite)** | state درون‌حافظه؛ نتایج در RAM و export فوری |
| **صف پردازش، چندپروژه‌ای، ریپازیتوری، lens موازی، IDF/شباهت/ضرایب ریاضی** | هیچ‌کدام؛ فقط موتور قانون‌محور |
| **هر فرمول ریاضیِ امتیاز یا نرمال‌سازی لگاریتمیِ شباهت** | منطق گسسته: دیوار(بولی)+حلقه(شعاع)+پُرسازی |
| **وزن‌دهی از «وزن دسته‌بندی/تم»** | تنها سیگنالِ رتبه‌بندیِ درون‌حلقه = **وزن ایمپرشن** |
| **تطابق روی `null == null`** | null=نامشخص؛ هر رابطه فقط با فیلدهای پرشدهٔ دو طرف |
| **پُرکردنِ سقف با کاندیدای بیرونِ دیوار (اسپم)** | پُرسازی لایه‌لایه؛ دیوارها هرگز شکسته نمی‌شوند |
| **شکستن دیوار قطبیت / قرنطینهٔ مبدأ / نردبان جغرافیایی** | طبق ARCHITECTURE.md دقیق پیاده شود |
| backendخارجی · axios · moment/date-fns · کتابخانهٔ concurrency/state | همگی ممنوع |
| منطق بیزینسی داخل کامپوننت React | منطق فقط در `src/core/*` و `src/services/*` |
| کامنت انگلیسی | تمام کامنت‌ها فارسی |

## آنچه از تجربهٔ قبلی نگه می‌داریم
ظاهر و فلوی کاربری (آپلود → فهرست صفحات → مشاهدهٔ کاندیداها → دکمهٔ AI → export) و تم بصری. فقط زیرساخت ساده و تمیز می‌شود.

## نبایدهای بحرانیِ افزوده (پس از دیباگ نسخهٔ ۱)
| ممنوع | الزام |
|---|---|
| **بی‌اثربودن محور نیت** | `intentAxis` باید **مستقیماً** حلقه‌بندی را عوض کند؛ خروجیِ صفحهٔ قیمت/مبدأ/فصل نباید مثل صفحهٔ شهری باشد |
| **سیلوی مبدأ به‌عنوان لینک درجه‌چندم** | اگر منبع `origin` دارد، «هم‌مبدأ در مقاصد مختلف» (ORIGIN_SILO) باید **حلقهٔ اولویت‌دار** باشد، نه R4 |
| **هاب ناخالص** | هاب = صفحه‌ای که **فقط** شهر/کشور دارد؛ وجود مبدأ/وسیله/مدت/ستاره/ترکیبی → دیگر هاب نیست |
| **لینک بین‌مقصدی به زیرصفحه** | TWIN/SUBREGION/CROSSSELL/PARENT فقط به **هابِ مقصد مقابل** («تور گرجستان») مجازند، نه «گرجستان نوروز/ارزان» |
| **غرق‌شدنِ حلقهٔ ۰** | صفحاتِ هم‌مقصد سقفِ نرم دارند؛ باید برای دوقلو/والد/بیش‌فروشی اسلات رزرو شود |
| **شکستن سیلوی زیارتی با مرز داخلی/خارجی** | اگر هر دو زیارتی‌اند، دیوار جغرافیایی شکسته می‌شود (کربلا↔مشهد↔نجف) |
| **صعود به صفحات قاره‌ای/تجمیعی غیرکانونی** | «تورهای آسیای شرقی»، «جام ملت‌ها» و … والد نیستند؛ فقط هابِ قارهٔ کانونی |
| **اعتماد به فیلد خامِ «جهت_در_منطقه» برای زیرمنطقه** | باید از نگاشتِ کیوریت‌شده استفاده شود (قفقاز جدا از آناتولی/آسیای‌مرکزی) |
| **نشت «null» در متن دلیل/انکر** | دلیل باید با نام مقصد و متناسب با رابطه ساخته شود؛ سال میلادی/بازهٔ دوساله پاک شود |
