# PROJECT.md — SemanticLink (پیشنهاد لینک داخلی مبتنی بر امبدینگ)

> نسخهٔ ۲.۰ — چرخش کامل معماری. **الگوریتم قانون‌محورِ «دیوار→حلقه→پُرسازی» به‌طور کامل حذف می‌شود.** جایگزین: شباهت معنایی واقعی از طریق امبدینگ برداری (Vector Embeddings) روی Supabase.

## هدف بیزینس
ابزار داخلیِ سبک برای تیم سئو: مجموعهٔ صفحات سایت (≈۶۰۰ صفحه، تگ‌خورده) یک بار امبد و در دیتابیس ذخیره می‌شوند؛ سپس برای **هر صفحه، ۳۰ صفحهٔ معنایی‌نزدیک** به‌عنوان کاندیدای لینک داخلی پیشنهاد می‌شود. یک لایهٔ هوش مصنوعیِ **اختیاری** می‌تواند این ۳۰ مورد را بازرتبه‌بندی (Re-rank) و دلیل سئویی تولید کند.

## پرسونای هدف
کارشناس سئو که کدنویس نیست. یک بار داده را وارد می‌کند، برای هر صفحه لیست پیشنهادها را می‌بیند، در صورت نیاز دکمهٔ «رتبه‌بندی هوشمند» را می‌زند، و خروجی CSV می‌گیرد.

## وضعیت: بازسازی (Re-architecture)
پروژه از یک SPA کاملاً client-side با موتور قانون‌محور، به یک SPA سبک + **بک‌اند Supabase** تبدیل می‌شود. کل منطقِ ربط از «قوانین هاردکد» به «شباهت برداری» منتقل می‌شود. هیچ فرمول/دیوار/حلقه‌ای باقی نمی‌ماند.

## فلسفهٔ معماری
یک منبع حقیقت (Supabase Postgres) + یک عملیات هستهٔ برداری (`pgvector`). ربط = **نزدیکیِ کسینوسی** بردارها. تگ‌ها صرفاً ورودیِ متنِ امبدینگ‌اند تا کیفیت بردار بالا برود؛ هیچ‌جا به‌صورت قانون گسسته اعمال نمی‌شوند. هوش مصنوعیِ چت یک لایهٔ **روکش (اختیاری)** است، نه بخشی از منطق پایه.

## پشته تکنولوژی (Tech Stack)
| لایه | ابزار |
|---|---|
| فریم‌ورک UI | React 19 + Vite 6 |
| زبان | TypeScript |
| استایل | **Tailwind CSS v4** (RTL، فارسی، تم emerald/slate) — از طریق `@tailwindcss/vite` |
| پارس CSV | Papa Parse v5 |
| بک‌اند | **Supabase** (Postgres + `pgvector` + Edge Functions) |
| دسترسی به دیتابیس | `@supabase/supabase-js` (کلاینت رسمی — **بدون ORM**) |
| امبدینگ | **`gemini-embedding-2`** با `output_dimensionality=768` + نرمال‌سازی L2 — فقط داخل Edge Function |
| مدل چت (Re-rank) | یکی از: `gemini-3.5-flash` \| `gemini-3.1-flash-lite` \| `gemini-3-flash-preview` (قابل انتخاب در تنظیمات) |
| state | `useState` + `useContext` (درون‌حافظه) |
| ماندگاری کلاینت | فقط `localStorage` برای **مدل انتخاب‌شده** (ترجیح UI، نه داده) |

## قرارداد مدل‌ها (Model Registry — الزامی)
تمام شناسه‌های مدل **فقط** در یک فایل واحد تعریف می‌شوند و از آنجا import می‌شوند (کلاینت + Edge Functions مقدار را دریافت می‌کنند):
- امبدینگ: `gemini-embedding-2` (ثابت) — بُعد خروجی `768`.
- چت (لیست انتخابی کاربر): `gemini-3.5-flash`، `gemini-3.1-flash-lite`، `gemini-3-flash-preview`.

> **نکتهٔ معمار:** این شناسه‌ها همان‌هایی هستند که کارفرما داد. چون ممکن است نام رسمی مدل‌ها تغییر کند، **هرگز به‌صورت رشتهٔ پراکنده هاردکد نشوند**؛ فقط از رجیستری خوانده شوند تا تغییرِ آینده یک‌نقطه‌ای باشد.

## نبایدهای سخت‌گیرانه (Anti-Patterns) — مطلق
| ممنوع | به‌جایش |
|---|---|
| **هر بازماندهٔ الگوریتم قانون‌محور** (walls/rings/fill/engine/worker، دیکشنری‌های هاردکد، `PageFeatures`، `intentAxis`، `impressionWeight`) | حذف کامل پوشهٔ `src/core/` و `src/workers/`؛ ربط فقط برداری |
| **محاسبهٔ شباهت در JavaScript** (کسینوس دستی، مرتب‌سازی بردار در کلاینت) | فقط RPC `match_pages` در Postgres با اپراتور `<=>` و ایندکس HNSW |
| **ذخیرهٔ بردار ۳۰۷۲‌بُعدی یا بردار ایندکس‌نشده** | `vector(768)` نرمال‌شده + ایندکس `hnsw (embedding vector_cosine_ops)` (سقف ایندکس pgvector = ۲۰۰۰ بُعد) |
| **قرار دادن `GEMINI_API_KEY` در کلاینت یا در باندل** | کلید فقط به‌صورت Secret در Supabase Edge Functions |
| **استفاده از سرور Express قدیمی (`server.ts`) به‌عنوان درگاه AI** | حذف Express؛ کلاینت مستقیم با Supabase و Edge Functions حرف می‌زند |
| **ORM (Prisma/Drizzle/…)** | فقط `@supabase/supabase-js` |
| **هاردکد کردن شناسهٔ مدل در چند فایل** | فقط از Model Registry |
| **`localStorage` برای داده** (صفحات/پیشنهادها/نتایج) | داده در Supabase؛ `localStorage` تنها برای مدل انتخاب‌شده |
| **منطق بیزینسی داخل کامپوننت React** | منطق در `src/services/*` و Edge Functions؛ کامپوننت‌ها Dumb |
| **ایمپرشن به‌عنوان سیگنال رتبه‌بندی** | رتبه‌بندی صرفاً معنایی؛ ایمپرشن فقط متادیتای نمایشیِ اختیاری |
| **کامنت انگلیسی** | تمام کامنت‌ها فارسی |
| **اجرای امبدینگ در حلقهٔ تک‌به‌تک بدون batch/backoff** | Edge Function دسته‌ای (chunk) با مدیریت خطا و نرخ |

## آنچه از تجربهٔ قبلی نگه می‌داریم
ظاهر و فلوی کاربری (آپلود → فهرست صفحات → دیدن کاندیداها → دکمهٔ AI → export)، تم بصری emerald/slate، RTL و فونت Vazirmatn، و پارسر CSV صفحات (`csvService`). فقط «مغزِ ربط» از قانون به بردار عوض می‌شود.
